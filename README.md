# Veridis Rewrite

Veridis Rewrite 是一个为 SillyTavern 准备的文本净化与 AI 局部改写扩展。你可以用规则直接替换或删除不想保留的词句，也可以让 AI 只改写被规则命中的句子；同时提供预设、范围保护、修改记录、Deep Clean、更新检查和匿名反馈等功能。

当前版本：`3.3`

第一次安装后会显示操作导览，主界面和 Deep Clean 的导览之后也可以再次打开。

使用、修改或再发布前，请阅读[许可与版权](#许可与版权)。

## 快速开始

1. 打开 Veridis Rewrite 工作台，新建一个预设或直接导入现成预设。
2. 启用需要的规则合集；普通规则会直接替换或删除命中内容。
3. 如果需要 AI Rewrite，在 AI 页面配置接口、模型和参数，再把对应规则设为“AI 改写”。
4. 保存预设后正常聊天即可。新生成的内容会按当前预设自动处理。
5. 想确认具体改了什么，可以点击消息旁的“净化前文透视”查看 Diff、相关规则或撤回净化。
6. 需要重新处理旧聊天、角色、人设、世界书等已有内容时，使用 Deep Clean。

## 功能说明

### 规则净化

支持普通文本、简易通配和正则表达式三种规则模式。规则可以按合集分组、单独启停、排序、搜索和批量管理，也可以为同一条规则配置多个替换候选；没有填写替换内容时，命中内容会被直接删除。

简易通配适合不想写正则时处理常见句式，例如 `*` 可匹配一小段内容，`{A,B,C}` 可表示多个候选写法。正则模式支持捕获组替换，例如 `$1`、`$2`。如果启用了简繁兼容，规则还可以扩展匹配常见的简体、繁体及地区异体写法。

### 预设与绑定

你可以保存多套净化预设，每套预设都拥有自己的规则和 AI Rewrite 配置。预设支持导入、导出、复制或移动规则合集，也可以设置全局默认预设，或把当前预设绑定到角色和 SillyTavern 的对话补全预设。

AI 接口本身也支持独立预设，方便在不同 Base URL、API Key、模型和生成参数之间切换。

### 范围保护

如果有内容不希望被净化，可以使用范围标签保护。既可以选择“保护标签内内容”，也可以反过来只处理指定标签里的内容。插件也支持跳过用户消息，并可在 Deep Clean 时保护用户人设，避免长期设定被误改。

### 净化前文透视

消息旁的 Diff 入口用于查看净化前后的变化。它会分别记录不同 Swipe 分支的修改轨迹，并区分 AI 改写、普通规则净化和手动修改。你可以查看片段或全文、追踪可能命中的规则，也可以把当前消息撤回到净化前的内容。

## AI 改写

AI Rewrite 不是整篇润色，而是只处理被 AI 规则命中的句子。3.3 开始，普通聊天会先让 AI 根据原文完成局部改写，再执行普通规则净化，最后一次性显示最终结果。

使用前需要启用酒馆助手（JS-Slash-Runner）相关能力，并在插件的 AI 页面配置 Base URL、API Key 和模型。AI Rewrite 使用的是插件里单独配置的接口，不会自动改用 SillyTavern 当前聊天正在使用的主模型。

默认会在指定的 XML 正文范围内寻找命中内容；你可以在 AI 设置里调整 XML 范围，留空时则按整条助手消息处理。不同 AI 规则也可以设置自己的改写要求。

如果 AI 没有发出请求，优先检查：AI 是否启用、接口与模型是否配置完成、规则是否真的命中，以及填写的 XML 标签是否完整闭合。AI 页面同时提供改写诊断和通信记录，方便查看实际请求和失败原因。

> AI Rewrite 会把需要改写的正文和上下文发送到你自己配置的接口服务。请自行确认所使用服务的隐私政策和数据处理方式。

## Deep Clean

Deep Clean 用来处理已经存在的内容，而不是只处理接下来新生成的消息。它可以选择聊天分支、角色、用户人设和世界书；在支持的情况下，也可以处理 Shujuku 中的相关数据。

你可以只运行普通规则，也可以选择“普通规则 + AI”。处理完成后可以先预览和编辑建议结果，再决定是否正式应用。若选择 Direct Apply，则会跳过逐条 Review 直接写入，请确认范围和规则后再使用。

打开或切换聊天时，Veridis Rewrite 不会自动把整段历史记录重新净化；如果你修改了规则并希望旧内容重新处理，请使用 Deep Clean 明确选择需要处理的范围。

## 反馈、更新与诊断

工具页可以查看插件版本、更新内容和更新状态，并在有可用更新时直接执行更新。

反馈中心支持提交 Bug 和功能建议，也可以按需附加运行环境、插件日志和 Deep Clean 诊断。发送前会先显示实际准备提交的内容，确认后再上传，方便你知道这次反馈具体带了什么信息。

AI 页面另有改写诊断和通信记录。如果遇到“规则命中了但 AI 没请求”“请求失败”“改写结果没有应用”等问题，优先从这里查看。

## 兼容与使用提示

Veridis Rewrite 适配 SillyTavern 的常规聊天、Swipe、消息编辑、流式和非流式生成，并处理 TauriTavern、柏宝箱、LoreFrame、MVU 等常见扩展场景。第三方扩展自身更新后，相关兼容行为也可能随之变化。

Shujuku 属于可选兼容项，不是使用 Veridis Rewrite 的必需依赖。AI Rewrite 则需要酒馆助手提供对应的生成能力。

如果同时启用了其他会修改同一段正文的正则、净化或改写方案，尽量避免让多套规则重复处理同一内容，否则最终结果可能互相覆盖或叠加。

## 数据与安全提示

- Deep Clean 在扫描、处理和普通 Review 阶段不会直接改写所选资源；正式修改发生在你确认 Apply 之后。Direct Apply 会跳过 Review。
- AI Rewrite 会把命中范围内需要参考的正文发送到你配置的接口服务。
- 使用正则或简易通配时，避免写出会匹配空字符串的规则。
- 不希望被处理的内容，优先通过范围标签、跳过用户消息或人设保护来明确排除。

### 2.6 版本更新

- API 预设管理调整：提供新建、保存、重命名和删除操作；“新建”会将当前 API、模型、生成参数与 XML 范围配置保存为独立预设，“保存”则更新当前选中的预设，不再隐式产生重复预设。
- 首页状态补全：首页显示规则组数量、AI 规则数量及 `AI 启用中 / AI 关闭中` 状态；移除首页原有的交互式模型列表拉取与状态控件，模型列表刷新统一保留在 AI 页面。
- AI 后台通信监视器：AI 页面可查看最新 10 次实际 `TavernHelper.generateRaw` 调用，每次调用或重试各自成条并按新到旧排列；记录已隐藏 API Key 的请求 JSON 快照、耗时，以及成功时的返回数据或失败时可取得的错误信息。此 TavernHelper 路径不提供 Token 用量、Provider HTTP 响应或 Provider 状态码。
- 改写诊断与状态显示：最新 60 条调试记录按新到旧展示，常用字段和阶段采用更紧凑、易读的中文标签，同时保留完整结构化 JSON 复制；可区分 Program Rewrite、AI Rewrite 与 Shujuku 事件。AI 改写成功通知会显示总耗时秒数，进度、成功和失败通知的布局更紧凑一致，进行中的通知仍可直接终止任务。
- 流式视觉净化性能：减少流式视觉投影中的冗余 DOM 处理和重复文本节点写入，降低持续生成时不必要的页面更新。
- 中文破折号视觉投影：对当前规则明确支持的中文 `——` 标点场景增加窄范围的实时显示处理；该处理只改变实时可见文本，不修改聊天数据、Swipe 数据、Diff 元数据或持久化内容，最终结果仍以 Program Rewrite 为准，并非无条件删除所有 `——`。
- 可选 Shujuku 兼容：工具页新增可主动启用的 Shujuku 数据库自动净化开关；Shujuku 完成自身数据库操作后，Veridis 可通过其可用的公共 API，将当前 Program Rewrite 规则应用到符合条件的单元格。重复或已消费的回调不会造成重复写入；Shujuku 不是必需依赖。
- Diff 生命周期修正：聊天与 DOM 的预备刷新保持为纯视觉操作，不再仅因刷新或预备 DOM 就持久化 Diff 元数据；Diff 持久化仍由正常生成与终稿收敛流程负责。
- 工作台界面整理：首页、净化、AI 与工具页的职责更清晰，桌面、平板和手机端的布局及页头行为统一；AI 改写对话框与通知采用更紧凑、一致的格式。

### 2.5 版本更新

- 流式视觉净化重构：移除增量源文本净化器，改为基于宿主已提交完整原文的逐帧视觉投影；不重建 `innerHTML`，不修改聊天、Swipe、Diff 或其他消息数据，并保留代码块、折叠控件和其他扩展持有的 DOM。
- 精确文本运行处理：普通内联包装和 `.text_segment` 节点可共享前后文，支持跨节点字面量、简易规则、捕获组和 lookaround；段落合并、拆分及跨换行规则继续只在最终整消息净化阶段执行。
- 锚点语义修正：`^` / `$` 仅在唯一可净化文本运行与去包装后的提交原文完全一致时参与实时投影；排除代码块或空结构块不再让唯一文本运行错误获得整条消息的起止语义。
- AI 生命周期收敛：自动改写绑定确定的聊天、generation、消息对象、楼层和 Swipe 分支；过期结果确定性拒绝，宿主终稿、AI 结果、程序净化与 MVU 尾部在一次最终原子提交中汇合。
- AI 请求与终稿可靠性：流式范围关闭、非流式首 Swipe、用户停止、regenerate、Swipe 重叠、设置变更和手动终稿均使用明确的所有权规则；失败或禁用路径按当前规则完成程序净化，不迁移旧任务或猜测写回位置。
- Diff 历史修正：透视内容来自已提交的原文/终稿轨迹，不再由当前规则重算历史；每个 Swipe 分支独立保留，全文模式按真实段落边界展示，历史窗口淘汰只清理插件自己的 Diff 元数据。
- 酒馆助手入口：新增由 TavernHelper 管理的输入框“AI 改写”按钮，点击后对当前聊天中最新一条助手消息执行手动 AI 改写；manifest 明确声明 `JS-Slash-Runner` 依赖。
- 结构维护：AI 改写、宿主生命周期、Diff 事件、AI 设置、设置迁移、聊天持久化和规则引擎拆分为职责明确的模块；原有 CSS 按固定级联顺序拆分为七个 partial，构建后的视觉级联保持一致。

### 2.4 版本更新

- AI 生成参数：支持温度、Top P、Top K、频率惩罚、存在惩罚、重复惩罚和最大输出 token；参数随 API 预设与净化预设保存。

- 共享上游配置：继续直接读取和保存 `ultimate_purifier_ai_rewrite` 下的规则、预设和 AI 设置。
- 旧改版设置迁移：共享设置为空时，可一次性导入 `ultimate_purifier_ai_rewrite_modified` 中的旧改版配置，且不删除原数据。
- 生成生命周期修正：SillyTavern 在 regenerate 建立新目标前删除旧助手消息时，不再误取消本轮自动 AI 改写；目标绑定后仍严格校验聊天、消息对象、固定楼层和 Swipe 分支，结构变化会终止旧任务而不会迁移写回位置。
- MVU 诊断补全：生成日志记录宿主 generation mode、dry-run、尾部消息结构和 MVU extra-model 状态，便于区分主生成、regenerate 与额外模型请求。
- Swipe 终稿持久化：AI 原子提交同时同步 `msg.mes`、当前 `msg.swipes[swipe_id]`、`msg.extra` 与当前 `swipe_info[swipe_id].extra`，生成新 Swipe 后返回旧分支不会恢复成改写前正文。
- 生命周期验证：generation identity、AI target policy 与 AI 终稿持久化契约由 Node 测试和独立验证脚本共同覆盖。
